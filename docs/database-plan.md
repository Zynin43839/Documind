# DocuMind Database Plan

## Scope And Decisions

The database supports a shared documentation corpus, Supabase Auth, per-user chat history, RAG retrieval, and citations that remain valid after documentation changes.

- Documentation is a shared corpus for all authenticated users.
- Historical citations must retain their original document-version provenance.
- The MVP has no conversation archive or delete capability.
- Supabase PostgreSQL with pgvector is the database platform.
- Gemini embeddings use the README contract of 768 dimensions and cosine similarity.

## Relationship Overview

```text
auth.users
  └── profiles

documentation_sources
  └── crawl_runs
  └── documents
        └── document_versions
              └── chunks
                    └── chunk_embeddings

profiles
  └── conversations
        └── messages
              └── retrieval_runs
                    └── retrieval_results
              └── message_citations
```

## Conventions

- Use UUID primary keys generated by `gen_random_uuid()`.
- Use `timestamptz` values in UTC with `now()` defaults.
- Use `created_at` and `updated_at` where a mutable record needs audit timestamps.
- Add a shared `set_updated_at()` trigger for mutable records.
- Enable `pgcrypto` and `vector` extensions in the first migration.
- Keep all Gemini calls, vector generation, crawl ingestion, and service-role credentials server-side.

## Identity

Supabase owns `auth.users`; application data must not duplicate credentials or email addresses.

### `profiles`

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key; references `auth.users(id)` with cascade delete |
| `display_name` | `text` | Non-empty trimmed name; maximum 80 characters |
| `created_at` | `timestamptz` | Default `now()` |
| `updated_at` | `timestamptz` | Default `now()`; maintained by trigger |

Create this record using a security-definer trigger after an `auth.users` insert. Use trusted user metadata with a safe fallback for `display_name`.

## Documentation And Crawl Lifecycle

### `documentation_sources`

One source is one documentation site and version scope, such as React 19 documentation.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `name` | `text` | Required |
| `root_url` | `text` | Required |
| `canonical_root_url` | `text` | Required and unique |
| `version_label` | `text` | Optional version identifier |
| `status` | `text` | `active`, `paused`, `archived`, or `failed` |
| `crawl_config` | `jsonb` | Default empty object |
| `last_crawled_at` | `timestamptz` | Optional |
| timestamps | `timestamptz` | Created and updated timestamps |

### `crawl_runs`

Immutable execution records for each crawler run.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `source_id` | `uuid` | Required reference to `documentation_sources` |
| `status` | `text` | `queued`, `running`, `succeeded`, `partial`, `failed`, or `cancelled` |
| `started_at`, `finished_at` | `timestamptz` | Execution timestamps |
| `pages_discovered`, `pages_processed`, `chunks_created` | `integer` | Non-negative counters, default 0 |
| `error_message` | `text` | Optional failure summary |
| `metadata` | `jsonb` | Default empty object |
| `created_at` | `timestamptz` | Default `now()` |

### `documents`

The stable identity for a canonical documentation page.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `source_id` | `uuid` | Required reference to `documentation_sources` |
| `canonical_url` | `text` | Required; unique with `source_id` |
| `status` | `text` | `active` or `retired` |
| `first_seen_at`, `last_seen_at` | `timestamptz` | Crawl lifecycle tracking |
| timestamps | `timestamptz` | Created and updated timestamps |

Canonicalize URLs before upserts. A page missing from a successful, full crawl becomes `retired`; do not hard-delete it immediately.

### `document_versions`

An immutable extracted representation of a document from a crawl run.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `document_id` | `uuid` | Required reference to `documents` |
| `crawl_run_id` | `uuid` | Required reference to `crawl_runs` |
| `title` | `text` | Optional page title |
| `content` | `text` | Required extracted text |
| `content_hash` | `text` | Required; unique with `document_id` |
| `is_current` | `boolean` | Default false; only one current version per document |
| `fetched_at` | `timestamptz` | Required |
| `metadata` | `jsonb` | Default empty object |
| `created_at` | `timestamptz` | Default `now()` |

Use a partial unique index on `(document_id)` where `is_current = true`. Mark a replacement version current only after its chunks and embeddings are available.

### `chunks`

Immutable retrieval segments from a document version.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `document_version_id` | `uuid` | Required reference to `document_versions` |
| `ordinal` | `integer` | Non-negative; unique with document version |
| `heading_path` | `text[]` | Default empty array |
| `content` | `text` | Required non-empty text |
| `content_hash` | `text` | Required |
| `token_count` | `integer` | Positive number |
| `char_start`, `char_end` | `integer` | Optional source offsets |
| `metadata` | `jsonb` | Default empty object |
| `created_at` | `timestamptz` | Default `now()` |

### `chunk_embeddings`

Keep embeddings separate from chunks so a model can be replaced without changing source provenance.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `chunk_id` | `uuid` | Required reference to `chunks` |
| `model` | `text` | Required embedding-model identifier |
| `embedding` | `vector(768)` | Required |
| `embedded_at` | `timestamptz` | Default `now()` |
| `created_at` | `timestamptz` | Default `now()` |

Enforce uniqueness on `(chunk_id, model)`.

## Conversations, Messages, And Citations

### `conversations`

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `user_id` | `uuid` | Required reference to `auth.users` |
| `title` | `text` | Required; default `New conversation` |
| `last_message_at` | `timestamptz` | Default `now()` |
| `created_at`, `updated_at` | `timestamptz` | Required timestamps |

This powers the history sidebar in the frontend mockup. Create a conversation lazily with the first user message.

### `messages`

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `conversation_id` | `uuid` | Required reference to `conversations` |
| `sequence_no` | `integer` | Positive and unique within a conversation |
| `role` | `text` | `user`, `assistant`, or `system` |
| `content` | `text` | Required non-empty text |
| `model` | `text` | Optional; assistant messages only |
| `created_at`, `completed_at` | `timestamptz` | Generation timestamps |

Persist the user message before generating an answer. Persist the assistant message after streaming completes.

### `retrieval_runs`

One record for the retrieval and generation operation initiated by a user message.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `user_message_id` | `uuid` | Required reference to `messages` |
| `assistant_message_id` | `uuid` | Optional reference to `messages` until completion |
| `embedding_model`, `generation_model` | `text` | Required model identifiers |
| `parameters` | `jsonb` | Retrieval count, threshold, prompt-template version |
| `status` | `text` | `running`, `succeeded`, or `failed` |
| `error_message` | `text` | Optional |
| timestamps | `timestamptz` | Created and completed timestamps |

### `retrieval_results`

Every chunk returned by the retrieval step, including chunks not ultimately cited.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `retrieval_run_id` | `uuid` | Required reference to `retrieval_runs` |
| `chunk_id` | `uuid` | Required reference to `chunks` |
| `rank` | `smallint` | Positive; unique per retrieval run |
| `similarity` | `real` | Required cosine similarity |
| `created_at` | `timestamptz` | Default `now()` |

Enforce uniqueness on `(retrieval_run_id, chunk_id)`.

### `message_citations`

The ordered citations displayed for an assistant answer.

| Column | Type | Rules |
|---|---|---|
| `id` | `uuid` | Primary key |
| `assistant_message_id` | `uuid` | Required reference to `messages` |
| `retrieval_result_id` | `uuid` | Optional reference to `retrieval_results` |
| `chunk_id` | `uuid` | Optional reference to `chunks` |
| `display_order` | `smallint` | Positive and unique per assistant message |
| `source_url`, `source_title`, `quoted_text` | `text` | Citation snapshot fields |
| `created_at` | `timestamptz` | Default `now()` |

Citation snapshots preserve the URL, title, and excerpt that supported an old answer even when the active document version changes.

## Indexes

```sql
CREATE INDEX conversations_user_recent_idx
  ON conversations (user_id, last_message_at DESC);

CREATE UNIQUE INDEX messages_conversation_sequence_idx
  ON messages (conversation_id, sequence_no);

CREATE INDEX crawl_runs_source_created_idx
  ON crawl_runs (source_id, created_at DESC);

CREATE UNIQUE INDEX documents_source_url_idx
  ON documents (source_id, canonical_url);

CREATE INDEX document_versions_document_created_idx
  ON document_versions (document_id, created_at DESC);

CREATE UNIQUE INDEX document_versions_one_current_idx
  ON document_versions (document_id) WHERE is_current = true;

CREATE UNIQUE INDEX chunks_version_ordinal_idx
  ON chunks (document_version_id, ordinal);

CREATE INDEX retrieval_results_run_rank_idx
  ON retrieval_results (retrieval_run_id, rank);

CREATE INDEX citations_message_order_idx
  ON message_citations (assistant_message_id, display_order);
```

Start with exact cosine search for a small corpus. Add this index once corpus size and measured latency justify it:

```sql
CREATE INDEX chunk_embeddings_hnsw_cosine_idx
  ON chunk_embeddings USING hnsw (embedding vector_cosine_ops);
```

## Retrieval Contract

The API generates a query embedding server-side, then calls a guarded RPC such as `match_documentation_chunks` with:

```text
query_embedding vector(768)
match_count integer default 5
source_ids uuid[] default null
similarity_threshold real default null
```

The RPC returns current chunks from active sources together with their page URL, title, section path, source name, distance, and similarity. It must limit `match_count` to a safe range and use cosine distance consistently.

## Security And RLS

- Enable RLS on all application tables.
- A user can read and update only their own profile.
- A user can read only conversations, messages, retrieval records, and citations belonging to their own conversations.
- Browser clients must not create assistant messages, citations, retrieval records, source records, documents, chunks, or embeddings.
- The shared corpus is not directly exposed to the browser; retrieval is mediated by Express or a guarded RPC.
- The crawler uses `SUPABASE_SERVICE_ROLE_KEY` only in trusted server-side code. Never expose this credential to Vite or the browser.
- Express validates the Supabase JWT for every chat request before it reads or writes user-owned records.

## Migration Plan

Use Drizzle as the only migration authority.

1. Add `drizzle.config.ts` and database schema definitions.
2. Create extensions and the common update-timestamp trigger.
3. Create `profiles` and its `auth.users` creation trigger.
4. Create source, crawl, document, version, chunk, and embedding tables.
5. Create chat, retrieval, result, and citation tables.
6. Add relational indexes, RLS policies, grants, and the retrieval RPC.
7. Add the HNSW index only after corpus-size and latency evaluation.

Run `drizzle generate` followed by `drizzle migrate` for schema changes. Do not use `drizzle push`.
