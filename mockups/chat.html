Rate limiting for API clients

What retry strategy should clients use when they receive a 429 response?

DM
DocuMindGrounded answer

For a 429 Too Many Requests response, retry only after the interval communicated by Retry-After. If that header is absent, use exponential backoff with jitter, beginning at one second and capping retries at five attempts.

Keep retries idempotent. For write operations, send an idempotency key so that a timeout or delayed response cannot create duplicate work.

HTTP response handling
const delay = retryAfter ?? 2 ** attempt + jitter();
await sleep(delay);

if (attempt >= 5) throw new Error("Retry limit reached");
