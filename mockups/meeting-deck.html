วาระที่ 1

ฟอนต์ภาษาไทย

ต้องเลือก 1 ตัว ปัญหา: Roboto (ของเดิม) ไม่มี glyph ไทย → ตอนนี้เว็บภาษาไทยจะ fallback เป็นฟอนต์ระบบ ดูไม่เนียน

ฟอนต์จุดเด่นเหมาะกับ
IBM Plex Sans Thai แนะนำ IBM ออกแบบให้จับคู่กับ Roboto/Roboto Mono ที่ใช้อยู่ · น้ำหนักหลากหลาย · ดู technical Dev tool — เข้ากับ design system เดิมที่สุด เปลี่ยนแค่ตัว font
Prompt กลมมน เป็นมิตร · ฟอนต์ไทยยอดนิยมของ Google อยากได้ feel friendly ไม่ formal
Sarabun ตัวกว้าง อ่านง่าย · ใช้แพร่หลายในเอกสาร เน้นอ่าน content ยาว แต่ดูทางการ
Noto Sans Thai มาตรฐาน Google · ครอบคลุมทุกภาษา ปลอดภัยสุด แต่หน้าตา generic

ตัวอย่างเทียบของจริงอยู่ใน mockups/font-logo-preview.html (เปิดใน browser)

วาระที่ 3

ปุ่มภาษา TH / ENG

ต้องตัดสินใจ 2 จุด

Default ภาษา?

  • Default ENG (ตามข้อสรุป) — เปิดหน้าแรกเป็นอังกฤษ
  • User กดปุ่มสลับ TH — จำค่าไว้ใน localStorage ครั้งถัดไปคงเดิม

ปุ่มสลับอะไรบ้าง?

  • UI เท่านั้น — ปุ่ม/หัวข้อ/label ในหน้าเว็บเปลี่ยนภาษา
  • รวมคำตอบ AI — ส่งภาษาไปกับ chat request ให้ AI ตอบเป็นภาษานั้น (ต้องเพิ่ม field language ใน API/prompt)

ข้อเสนอ: default ENG + สลับทั้ง UI และคำตอบ AI (ส่งภาษาไป backend) — เป็นเอกภาพกับ "output ไทยต้องแม่น"

วาระที่ 5

ข้อตกลงการใช้ Git

ยืนยันกติกา ข้อสรุปจากประชุม: ก่อน merge ต้อง review · ก่อน push ต้อง review

หัวข้อข้อเสนอ
Branchทำงานใน feature/ชื่องาน แล้ว merge เข้า main
ก่อน Mergeต้องมีคน (ทีม 2 คน) review code ให้ผ่านก่อน merge
ก่อน Pushตรวจ + review ก่อน push ขึ้น remote
Commit messageเขียนสั้น ตรงไปตรงมา อธิบายว่าทำอะไร (ดูแนวทาง commit เดิม)
บันทึกเป็นกฎเขียนลง AGENTS.md ของโปรเจกต์ให้ AI และทีมทำตามเดียวกัน

วาระที่ 6

เอกสารหลายเวอร์ชัน — จัดการยังไง

โจทย์: doc บางอันอัปเดตหลายครั้ง (เช่น React 18 route อัปเดต 5 ครั้ง) — ถ้า user ยังใช้เวอร์ชันเก่า เราไม่ควรลบของเก่าออกจาก DB

แนวทางเดิม

"เอาอันเก่าออก ใส่อันใหม่" — ง่าย แต่พังเพราะ user ที่ใช้เวอร์ชันเก่าจะเห็นคำตอบอ้าง doc ที่ไม่อยู่แล้ว

แนวทางใหม่ (schema รองรับแล้ว)

เก็บทุกเวอร์ชัน: ตาราง document_versions + flag is_current — คำตอบเก่า cite version เดิมได้แม้ doc อัปเดตแล้ว

-- database-plan.md ตอบโจทย์นี้แล้ว documentation_sources -- 1 แหล่ง = 1 เว็บ + 1 version scope └─ crawl_runs └─ documents -- ตัวตนของหน้า (canonical_url) └─ document_versions -- แต่ละ crawl = version, is_current └─ chunks └─ chunk_embeddings

ที่เหลือต้องตกลง: จะให้ AI ค้นจากเวอร์ชันไหน? (เฉพาะ is_current ในการค้น, cite เก็บ snapshot ของ version ที่ตอบ) — schema วางไว้ให้แล้ว
